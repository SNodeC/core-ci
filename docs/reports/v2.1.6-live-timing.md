## Measurement boundaries

Temporary Linux uprobes record entry and return timestamps for 32 controller functions and
callback boundaries. They are limited to the running controller PID, use a dedicated trace
instance, capture no request bodies, credentials or arguments, and do not change controller
sources or its persisted state. Server timestamps use a monotonic clock correlated with UTC;
the server reports synchronized system time. Trace overhead is present: this is an instrumented
Debug run, not an uninstrumented Release benchmark.

Function durations are synchronous inclusive wall durations, not CPU time or completion time
for asynchronous work. The SQL queue wait and derive-return-to-apply-entry spans are separate
asynchronous elapsed measurements. The latter includes database/network wait and event-loop
scheduling; it is not a pure server SQL execution measurement. Nested function times must not
be summed as independent work. The analysis also computes self time and the union of traced
synchronous intervals to avoid double counting. Observer GETs and public status-worker GETs
are included in process-level view/render timings.

A persistent SSE observer records every received graph frame. Its timestamps are client
observation times, including server rendering, transport and local scheduling. They are not
exact SQL commit timestamps. GitHub job timestamps have one-second resolution. Consequently,
job-finish-to-SSE differences include webhook delivery, controller processing and observation
transport; they must not be labelled controller CPU time.

GitHub runs are sampled about once a minute; completed attempt-one jobs and their steps are
saved once. These observer REST calls are separate from the controller's request count.
Controller public facts, the served Pages JSON and four HTML status pages are sampled about
every 30 seconds. Their first-visible times therefore have sampling uncertainty. A separate
HTML sampler retains distinct rendered bytes. Chrome observes the live management page and
its SSE-driven graph without clicking mutation controls. Chrome's first attempted target was
a background extension page; that sample was blank and is excluded. The watcher was corrected
to select the actual page target.

## Independent progression and publication

SSE frames are checked for prerequisite publication and child assignment in the same graph
frame. A child must not be left waiting once its exact prerequisites are published and it is
otherwise eligible. Publication workflows include artifact validation, feed-write admission,
privileged feed preparation/push and secret-free public confirmation. The final controller
receipt proof is another boundary. These phases are analysed separately.

At 11:58:08 UTC, separate observations found controller generation 2377, repository feed
snapshot generation 2364 and served Pages generation 2348. This proves that the surfaces were
at different boundaries. It does not by itself identify the whole delay's owner. Pages serves
`Cache-Control: max-age=600`; a sample at 11:57:00 had `Age: 0`, `X-Cache: MISS` and modification
time 11:56:55. That sample is not proof that earlier stale responses were caused by caching.

## Assessment and remaining work

The functional full-chain run passed: 40 successful workflows, 20 verified publications,
correct dependency release, final UI/SSE consistency and all 20 rendered public rows matching.
No 403 or uncertain dispatch was reported in controller diagnostics for this session.

Performance is not accepted merely because the run completed. The measured improvement
target of near-negligible total controller work is not achieved by this Debug deployment.
The high-cost local paths are graph/SQL preparation and derived presentation/application;
the high-cost workflow paths include privileged preparation and redundant status refreshes.
The next performance work should distinguish these sources and measure them independently.
There is no comparable instrumented baseline for a 10–20 times speedup claim.

All temporary uprobes and the dedicated trace instance were removed. The controller remains
active with PID 223081/NRestarts 0. No controller source, configuration, production SNodeC
resource or test changed. The new tag and automated sandbox package/status publications
are the authorized external mutations. The report and WORK_LOG entry are uncommitted.
